# Dayflow Android 개발 제안서

작성일: 2026-10-07 · 상태: 개발 착수 (사용자 명시 지시)

## 1. 목적과 확정 요구사항

Windows Dayflow의 기록을 휴대폰에서 간편하게 작성하고, 갤럭시 탭에서는
넓게 펼쳐 쓰는 안드로이드 앱을 만든다. 하나의 APK가 두 기기를 지원한다.

- 새 저장소 이름: `Dayflow-apk`, 기존 `cybereun/Dayflow`와 분리.
- 작업 위치: `Y:\내 드라이브\AI\App_Bulid\Dayflow-apk`.
- 기존 Windows 코드·저장 데이터·릴리즈는 변경하지 않는다.
- 태블릿 가로 화면은 기존 데스크톱의 구성과 종이 플래너 분위기를 유지한다.
- 휴대폰은 같은 데이터를 모바일 전용 배치로 보여준다.
- 승인한 본인 기기끼리 기존 Dayflow 전용 Cloudflare 서버로 동기화한다.
- 풍경 배경은 넣지 않고 종이·파스텔 포인트·기존 9가지 컬러를 유지한다.
- 선택한 기본 컬러가 테마 포인트 전반에 반영되어야 한다.

이하 기술 선택과 단계별 범위는 제안이며, 문서 승인 후 구현 계획을 확정한다.

## 2. 기술 방식 비교와 추천

| 방식 | 장점 | 부담 | 판단 |
| --- | --- | --- | --- |
| Kotlin + Jetpack Compose | 터치·키보드·화면 전환·탭 대응을 네이티브로 설계 | PC 화면과 동기화 모듈을 Android에 맞게 구현해야 함 | 추천 |
| Capacitor + 웹 UI | 웹 기반 화면·데이터 로직 재사용 가능 | Electron/Node API는 그대로 실행 불가, 보안 저장·암호화 브리지 필요 | 대안 |
| Flutter | 하나의 UI 코드로 다양한 플랫폼 확장 가능 | 현재 Android 외 플랫폼 요구가 없고 별도 언어·구조 추가 | 이번에는 제외 |

추천 구성은 Kotlin, Jetpack Compose, 로컬 Room 저장소, Android Keystore,
네트워크 클라이언트와 WorkManager다. API 최소 버전은 Android 8.0(API 26)을
목표로 하되, 암호화 라이브러리 호환성을 먼저 검증한다. 지원 범위를 임의로
높이지 않고 호환성 문제가 생기면 사용자에게 알린다. 패키지 ID 제안은
`com.cybereun.dayflow`, 앱 표시 이름은 `Dayflow`, 첫 버전은 `0.1.0`이다.

Google 공식 문서는 기기 명칭이 아니라 앱에 실제로 주어진 화면 공간에 따라
배치를 바꾸는 방식을 안내한다. 따라서 탭의 분할 화면도 별도 처리한다.

참고:
- https://developer.android.com/develop/ui/compose/build-adaptive-apps
- https://developer.android.com/develop/adaptive-apps/guides/support-different-display-sizes
- https://capacitorjs.com/docs

## 3. 화면과 기능

### 휴대폰

하단 메뉴: 오늘 / 주간 / 통계 / 설정.

- 오늘: 날짜 이동, D-day, 할 일 작성·순서 변경·상태 표시, 코멘트,
  총 기록 시간, 메모, 시간표 바로가기.
- 시간표: 별도 넓은 화면, 형광펜 선택, 터치·드래그로 칸 기록·지우기.
  셀 구간과 시간 범위는 PC 데이터 구조를 읽어 동일하게 적용한다.
- 주간: 날짜 선택과 하루 단위 전환. 작은 화면에 7열을 강제로 축소하지 않는다.
- 통계: 이번 주·이번 달·일 평균·기록일·연속 기록·완료율,
  최근 12주·시간대·요일·할 일 상태·형광펜별 시간·최근 35일 기록.
  휴대폰에서는 세로 카드로 배치하되 계산 의미는 PC와 동일하게 한다.
- 설정: 플래너 관리, 테마·9가지 컬러, 형광펜 관리, 동기화,
  백업 내보내기·복원, 개인정보·앱 정보.

### 갤럭시 탭

- 넓은 가로: 일간은 왼쪽 할 일·메모 / 오른쪽 시간표,
  주간은 7열, 홈 통계는 데스크톱과 같은 정보 배치.
- 세로·중간 너비: 2단 또는 선택한 날짜 중심 배치.
- 분할 화면·작은 너비: 휴대폰형 배치로 자동 전환.
- 글자·아이콘·선·배경색은 실제 컴포넌트 위치에 맞춰 그린다.
  PC 전체 화면을 이미지로 축소하거나 스크린샷 배경을 붙이지 않는다.
- 터치 영역은 최소 48dp를 목표로 한다. 글꼴 확대·키보드 표시 때도
  입력칸과 저장 동작을 가리지 않는다.
- S펜은 기본 터치/포인터 입력을 지원한다. 자유 필기·필압·필기 인식은
  기존 기능과 다른 기능이므로 1차 범위에 포함하지 않는다.

## 4. 데이터와 동기화 설계

PC의 `library` 및 플래너 JSON 구조를 기준으로 호환 어댑터를 만든다.
로컬 DB는 화면을 위한 저장 방식일 뿐, 서버에 전송하는 데이터 의미를
바꾸지 않는다. 모르는 필드도 보존하여 모바일 저장 때문에 PC 전용 설정이
사라지지 않게 한다. 플래너 ID·날짜 키·시간 칸·할 일 상태를 임의 변환하지 않는다.

- 오프라인 우선: 먼저 로컬 트랜잭션으로 저장하고 전송 대기 상태를 보존한다.
- 서버: `https://dayflow-sync.cybereunny.workers.dev`, protocol v1.
- 그룹별 기기 토큰과 그룹 키로 A/B 사용자를 분리한다.
- 연결: 8자리 코드 → 새 기기의 6자리 확인 숫자 → 기존 기기 승인.
- 암호화: PC와 동일한 AES-256-GCM, AAD, HMAC 레코드 ID,
  X25519/HKDF 연결 키 형식을 테스트 벡터로 검증한다.
- Android Keystore로 로컬 비밀 정보를 보호한다. 비밀키·토큰·복구 코드는
  로그·Git·오류 보고에 포함하지 않는다. 동기화 인증 파일은 OS 자동 백업에서 제외한다.
- 항목별 시각·삭제 표식·CAS 재시도 규칙을 동일하게 구현한다.
  동시 편집에서 다른 칸의 수정이 사라지지 않고 삭제 항목이 되살아나지 않아야 한다.
- 앱 사용 중에는 약 15초 확인과 수동 동기화를 제공한다.
  백그라운드는 Android 배터리 정책을 따르므로 15초 주기를 보장하지 않는다.
  앱 복귀·네트워크 회복 시 다시 시도한다. 상시 실행 서비스는 만들지 않는다.
- 동기화 기본값은 꺼짐. 기존 PC 앱 v1.0.12에는 이 프로토콜이 없으므로
  Android↔PC 검증은 v1.0.13 소스 실행 환경으로 한다.
  Windows 설치 파일 제작은 별도 지시가 있을 때 진행한다.
- 기기 차단은 이후 접근만 막는다. 이미 내려받은 데이터의 원격 삭제나
  그룹 키 자동 회전으로 설명하지 않는다.

## 5. 구현 순서와 단계별 완료 기준

1. 기반·호환 계약: 새 저장소, Android 빌드 기반, PC 데이터 샘플과
   암호화 테스트 벡터. PC 암호문을 Android가 읽고 그 반대도 통과.
2. 로컬 기록: 오늘·할 일·코멘트·메모·시간표, 플래너 관리,
   오프라인 저장·재실행 복원. 종료·회전·분할 화면에서 데이터 유지.
3. 공용 화면: 휴대폰/탭 레이아웃, 주간·통계, 테마와 9색.
   대표 화면 크기별 스크린샷으로 겹침·잘림·간격 확인.
4. 동기화: 신규 그룹·합류·승인·수동/자동 동기화·복구·기기 해제.
   PC↔폰↔탭 동시 수정, A/B 분리, 오프라인 재전송 검증.
5. APK 검증: 로컬 단위/통합 테스트, 에뮬레이터 또는 연결 기기 설치,
   백업·복원·권한·릴리즈 서명 점검. 테스트 APK와 검증 결과 전달.

디버그 APK와 실제 배포용 서명 APK를 명확히 구분한다. 배포 키는 저장소에
올리지 않고 안전한 별도 위치에 보관한다. APK 서명 키가 달라지면 기존 설치본
업데이트가 안 되므로 최종 배포 전 키 관리 방식을 확정한다.

## 6. 범위 제외와 비용

1차 제외: iOS, 여행 기능, 다른 사람과 공동 편집, 소셜 로그인,
AI 기능, 자유 필기 인식, 위젯·알림, Play Store 등록, Windows 릴리즈 제작.
계정 없는 본인 기기 연결을 우선한다. QR 추가는 숫자 코드 방식 검증 이후 별도 판단한다.

개발 도구와 로컬 APK 제작은 무료 도구를 우선한다. 기존 Cloudflare의 무료
범위를 우선 사용하되 무제한이라고 약속하지 않는다. 유료 서비스·요금제 전환은
동의 없이 하지 않는다. 스토어 등록 비용은 이번 APK 직접 설치 범위와 별개다.

## 7. 현재 상태와 승인 요청

기존 PC 저장소의 동기화 모듈과 문서를 읽기 전용으로 확인했다.
새 폴더에는 이 제안서만 작성했다. 앱 코드·GitHub 저장소·서명 키·APK는
아직 생성하지 않았다. 이 문서를 승인하면 상세 구현 계획을 작성하고
검토 후 직접 순차 구현한다. 사용자 요청 없는 병렬 에이전트 작업은 하지 않는다.

승인 대상: Kotlin 네이티브 방식, 위 1차 범위, 기존 PC와 동기화 호환,
휴대폰·탭 공용 APK, 자유 필기/스토어 등록 제외.

## 8. 착수 시 확정 사항

사용자가 '빨리 시작해'라고 구현 착수를 지시했다. 추가 승인 질문을 반복하지
않고 직접 순차 구현한다. 자유 필기·필기 인식은 보류한다. 종이 질감·9색·
제목과 선·체크박스 등 데스크톱의 디자인을 최대한 유지하고 화면 배치만
기기에 맞춘다. 첫 단계는 로컬 기록/공용 화면 APK, 이후 동기화 통합 순서다.
GitHub 새 저장소는 공개 범위를 임의로 넓히지 않도록 비공개로 생성한다.
