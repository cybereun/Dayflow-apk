# Dayflow 손글씨·필기 원본 동기화 설계

상태: 사용자 검토용. 제품 코드 구현 및 배포 전 승인 필요.

## 1. 범위와 배포 대상

- Android: `Y:\내 드라이브\AI\App_Bulid\Dayflow-apk`, v1.0.16 / versionCode 16.
- Windows: `Y:\내 드라이브\AI\App_Bulid\Dayflow`, v1.0.18. 현재 공개 최신 버전은 v1.0.17.
- Android에 한글 손글씨를 텍스트로 입력하는 기능과 자유 필기 저장을 추가한다.
- Windows에는 동기화한 자유 필기를 원래 페이지 위치에 읽기 전용으로 표시한다.
- 기존 Android 업데이트 기능을 이번 APK에 포함한다. 공개 GitHub 릴리즈에서 이후 높은 버전을 확인한다.
- 각 저장소의 요청 범위 변경만 커밋·푸시하고, 검증한 서명 패키지와 릴리즈 설명을 업로드한다.
- 디자인 변경, 기존 입력 기능 재구성, 계정·동기화 그룹 초기화는 제외한다.

## 2. 보존 원칙

- 기존 기록, 동기화 그룹, 기기 승인, 암호화 키, 복구 코드를 삭제하거나 재발급하지 않는다.
- 작업 전 기존 저장소의 백업 경로와 복구 가능성을 확인한다. 테스트는 별도 테스트 플래너/그룹을 사용한다.
- 사용자 실데이터에서 전체 삭제·재가입·앱 삭제·스토리지 초기화를 하지 않는다.
- 새 필드는 추가형으로 도입한다. 마이그레이션 실패 시 원본을 보존하고 동기화를 중단·안내한다.
- 읽을 수 없는 새 데이터는 빈 데이터로 대체하지 않는다.
- 기존에 수정 중인 다른 파일은 보존한다. Android의 이전 태블릿 수정·업데이트 기능은 사용자 요청의 연속 작업으로 구분해 diff를 검토한다.

## 3. 입력 및 화면

### 손글씨 → 텍스트

- 기존 텍스트 입력칸에 포커스한 후 필기 입력 도구를 연다.
- 별도 필기판에 펜 또는 손가락으로 작성한다. 한글을 기본 인식 언어로 사용한다.
- 인식 후보를 사용자가 확인·선택한 후 해당 입력칸에 삽입한다. 자동으로 기존 글을 덮어쓰지 않는다.
- 대상은 태스크, 코멘트, 메모, 목표, D-day 제목 등 일반 텍스트 입력칸이다. 날짜 선택값에는 임의 텍스트를 삽입하지 않는다.
- Google ML Kit 기기 내 디지털 잉크 인식을 검토한다. 언어 모델 최초 다운로드 상태·실패·재시도를 표시한다. 모델이 없거나 인식이 실패해도 필기 원본을 버리지 않는다.
- Android 14 이상 OS 필기 지원과 별개로 Android 9 테스트 태블릿에서도 사용할 앱 내 필기판을 제공한다.

### 필기 그대로 저장

- 일간·주간 플래너 페이지 위에 명시적인 펜 모드를 제공한다. 홈 통계·설정 화면에는 필기하지 않는다.
- 펜 모드 밖에서는 기존 터치·텍스트 입력·형광펜 동작을 유지한다.
- 색상·굵기 선택, 획 단위 지우개, 실행 취소·다시 실행을 제공한다.
- S펜 사용 중 손바닥 접촉은 획으로 저장하지 않는다. 손가락 필기는 별도 선택으로 허용한다.
- 페이지 논리 좌표에 획을 저장한다. 기기 해상도·회전·확대 배율을 저장 좌표에 섞지 않는다.
- 태블릿 양면 페이지는 각각 날짜에 귀속된다. 가운데 링·팔레트·상단 안내창에는 쓰지 않는다.
- 필기판/펜 도구 추가 외 기존 종이·팔레트 디자인을 유지한다.

## 4. 저장 방식 비교 및 권장안

1. PNG만 저장: Windows 표시가 단순하지만 수정 시 재인코딩·전송량이 크고 확대하면 흐려질 수 있다.
2. 펜 획 원본 저장 후 렌더링(권장): 위치·색·굵기를 유지하고 획 단위 병합·지우기가 가능하다. Windows에서 그림처럼 표시한다.
3. 서버에 이미지 첨부 업로드: 별도 파일 저장·권한·삭제 정책이 필요하므로 이번 범위에서는 피한다.

권장안은 획 원본을 단일 정규 데이터 모델로 저장하고, 각 앱이 같은 좌표 규칙으로 그리는 방식이다. 사용자에게 Windows에서는 읽기 전용 이미지처럼 보인다. 원본과 PNG를 동시에 권위 있는 데이터로 저장하지 않는다.

## 5. 데이터 및 동기화

- 획에는 고유 ID, 플래너 ID, 페이지 종류, 날짜/주 시작일, 논리 좌표 점열, 색상, 굵기, 수정 시각/논리 시계, 삭제 표시를 둔다.
- 기존 텍스트·시간표 데이터와 별도의 필기 레코드 영역을 사용한다. 저장량·점 개수 상한과 입력 검증을 두고 단순화로 과도한 크기를 방지한다.
- 기존 Cloudflare 동기화와 동일한 승인 기기 그룹 및 종단간 암호화 원칙을 유지한다. 평문 필기나 암호화 키를 공개 파일 서버에 올리지 않는다.
- 기존 엔진이 임의 새 필드를 보존하는지 먼저 테스트한다. 보존하지 않는다면 엔진의 기존 데이터 병합에 새 필드를 억지로 끼워 넣지 않고, 버전이 명시된 필기 전용 암호화 레코드 경로를 양쪽 앱에 추가한다.
- 필기 전용 경로가 필요하면 기존 Worker 안에서 격리해 추가한다. 기존 그룹·기기 인증을 검증하고 기존 경로·레코드는 변경하지 않는다.
- 새 획은 ID별 추가, 지우기는 해당 획의 삭제 표시로 병합한다. 다른 기기에서 동시에 추가한 획을 페이지 전체 덮어쓰기로 잃지 않게 한다.
- Windows의 읽기 전용 표시는 삭제·편집 요청을 만들지 않는다.
- 오프라인 작성 후 재연결, 앱 재실행, 재전송이 중복 획·부활을 만들지 않게 한다.
- 구버전 앱의 저장·동기화가 새 필기 레코드를 지우지 않는 호환성 테스트를 필수로 한다.

## 6. 업데이트 및 릴리즈

- Android v1.0.16에 업데이트 확인 기능이 처음 포함된다. 기존 v1.0.15 이용자는 v1.0.16을 한 번 수동 설치해야 한다.
- 이후 더 높은 태그·versionName·versionCode의 동일 서명 APK에 업데이트 안내를 제공한다.
- Android 설치는 사용자 다운로드 동의와 시스템 설치 승인을 요구한다. 무인 설치는 하지 않는다.
- Windows 기존 업데이트 체계를 유지하고 v1.0.18의 설치·재실행 및 업데이트 피드를 검증한다.
- APK/설치파일의 SHA-256과 버전·서명을 확인한 후 업로드한다. Git 푸시만으로 배포 성공을 주장하지 않는다.
- 기존 공개 버전 파일을 삭제·덮어쓰지 않고 새 버전 릴리즈를 추가한다.

## 7. 완료 기준

- Android 9 실제 태블릿에서 펜 획 작성·저장·재실행 복원·회전·확대 후 위치가 유지된다.
- 실제 S펜 입력과 손바닥 거부는 사용자 펜 입력으로 검증한다. 자동 터치 테스트만으로 펜 검증을 대체하지 않는다.
- 한글 인식 결과를 태스크와 메모에 넣고 재시작 및 기존 텍스트 동기화로 보존한다. 오인식 가능성을 안내한다.
- Android에서 작성한 획이 Windows 같은 플래너·날짜·좌표에 표시된다.
- 오프라인 재연결·동시 작성·삭제 표시·구버전 클라이언트 동작에서 기존 기록과 필기 원본이 보존된다.
- 다른 그룹은 필기 레코드를 조회할 수 없다. 인증 없는 요청과 잘못된 데이터는 거부한다.
- 기존 테스트, 추가 데이터/좌표/병합/업데이트 회귀 테스트, 양쪽 빌드와 설치 검증 결과를 기록한다.
- 양쪽 저장소의 푸시 커밋과 공개 릴리즈 URL, 실제 업로드 파일을 확인한다.

## 8. 승인 후 순서

데이터 보존·호환성 시험 → 구현 계획 → 필기 모델/저장/암호화 동기화 → Android 입력/인식 → Windows 표시 → 기기 간 검증 → 버전 변경·빌드·푸시·업로드.

현재 문서는 설계이며, 필기 기능을 구현하거나 릴리즈한 상태를 의미하지 않는다.
